> **대회가 끝난 뒤 이 자료를 외부에 배포하면 안 됩니다.**

## 시작 템플릿

`template.yml` 은 **입출력 규격만 맞춰 둔 빈 워크플로**입니다. 가져와서 가운데
노드를 여러분의 것으로 바꾸면 됩니다.

```
시작 (지문 PDF, 정해)
 ├→ 지문 추출
 └→ 정해 추출
      ↓
   여기부터 여러분의 차례
      ↓
   종료 (gen, script)
```

가져오는 방법입니다.

1. Dify 스튜디오에서 **앱 만들기 → DSL 파일 가져오기**
2. `template.yml` 선택
3. 채점 도구를 쓰려면 **커스텀 도구**를 따로 등록합니다 (`https://judge.6r33n.kr/openapi.json`)

**가져오자마자 한 번 실행해 보십시오.** 가운데에 LLM 이 아니라 template-transform 노드를 넣어
두어서 모델 자격 증명 없이도 그대로 돌아갑니다. 입출력이 통하는지 눈으로 먼저 확인하고,
그 노드를 지운 자리에 여러분의 모델로 LLM 노드를 붙이면 됩니다.

커스텀 도구는 DSL 에 담기지 않습니다. Dify 의 DSL 이 자격 증명을 포함하지 않기 때문입니다.

템플릿에는 규격 세 가지가 미리 맞춰져 있습니다. 직접 만들면 반드시 걸리는 지점들입니다.

- `.cpp` 는 기본 문서 목록에 없어서, 파일 형식에서 사용자 지정을 켜야 정해를 올릴 수 있습니다.
- 지문이 PDF 라 문서 추출 노드가 필요합니다. LLM 노드 하나로는 시작조차 못 합니다.
- 파일 개수 한도가 기본값이면 지문과 정해를 한꺼번에 받지 못합니다. 둘까지 받도록 올려 두었습니다.

**이 템플릿을 꼭 써야 하는 것은 아닙니다.** 빈 앱에서 시작해도 되고, 입출력 이름만 맞으면
어떻게 만들든 상관없습니다.

## testlib

뿌리에 놓인 `testlib.h` 는 **채점 서버가 쓰는 것과 같은 파일**입니다. 버전은 `0.9.42-SNAPSHOT`
입니다. 다른 버전을 받아 쓰면 채점 결과가 달라질 수 있으니 이 파일을 그대로 쓰십시오.
채점 도구의 `run_code` 에도 같은 파일이 함께 놓여 있어서 `#include "testlib.h"` 가 바로 됩니다.

`testlib_공식문서.md` 는 testlib 공식 저장소의 기술 문서를 그대로 옮긴 것입니다.
체커, 인터랙터, 검증기, 생성기의 표준 뼈대가 예제 코드로 들어 있습니다.

더 자세한 공식 해설은 아래에서 볼 수 있습니다.

- 생성기: <https://codeforces.com/blog/entry/18291>
- 검증기: <https://codeforces.com/blog/entry/18426>
- 체커: <https://codeforces.com/blog/entry/18431>

## 문제지 PDF

`문제지_예비소집.pdf` 와 `문제지_본대회.pdf` 는 두 라운드의 전체 문제지입니다.

**주의하십시오.** 이 문제지에는 투 스텝이나 인터랙티브처럼 **입력으로 주어지는 문제의 형식에
맞지 않는 문제도 섞여 있습니다.** 여러분의 애플리케이션이 받게 될 문제는 표준 입출력으로
채점하는 문제뿐입니다.

## 문제별 자료

파일 이름은 폴리곤 패키지의 관례를 그대로 따랐습니다.

### 예시 A+B

| 파일 | 무엇인가 |
|---|---|
| `statement.pdf` | 지문 |
| `main.cpp` | 정해 |
| `validator.cpp` | 검증기 |
| `gen.cpp` | 예시 생성기 |
| `example.01` | 예제 입력 |
| `example.01.a` | 예제 출력 |

### 예비소집 A 저울

| 파일 | 무엇인가 |
|---|---|
| `main.cpp` | 정해 |
| `validator.cpp` | 검증기 |
| `gen.cpp` | 예시 생성기 |
| `statement.pdf` | 지문 |

### 예비소집 E 매직쌀

| 파일 | 무엇인가 |
|---|---|
| `statement.pdf` | 지문 |
| `validator.cpp` | 검증기 |
| `checker.cpp` | 스페셜 저지 (체커) |

### 본대회 N 매직쌀2

| 파일 | 무엇인가 |
|---|---|
| `statement.pdf` | 지문 |
| `validator.cpp` | 검증기 |
| `checker.cpp` | 스페셜 저지 (체커) |

`main.cpp` 는 그 문제의 정답 프로그램이고, `validator.cpp` 는 입력이 지문의 제한을 지키는지
검사하는 프로그램입니다. `gen.cpp` 는 testlib 로 쓴 생성기의 예시이며, 여러분의 애플리케이션이
만들어 낼 결과물이 어떤 모양이어야 하는지 보여 줍니다.

`checker.cpp` 가 있는 두 문제는 답이 여러 개일 수 있어 스페셜 저지를 씁니다.
**본 채점에는 스페셜 저지가 필요한 문제가 나오지 않습니다.** 참고 자료로만 보십시오.

## 컴파일

`testlib.h` 가 뿌리에 있으므로, 문제 폴더 안에서 `-I..` 로 헤더 위치만 알려 주면 됩니다.

```
cd 1_예시_A+B
g++ -O2 -std=c++20 -I.. -o gen gen.cpp
./gen
```

**두 예시 생성기는 결과를 내는 방식이 서로 다릅니다.** 둘 다 정식으로 인정되는 방식입니다.

| 생성기 | 방식 |
|---|---|
| `1_예시_A+B/gen.cpp` | 한 번 실행하면 `1.in` 부터 차례로 **파일을 직접 남깁니다** |
| `2_예비소집_A_저울/gen.cpp` | 실행할 때마다 케이스 하나를 **표준 출력으로 냅니다** |

두 번째 방식은 폴리곤의 Generator Script 처럼 인자를 바꿔 가며 여러 번 부르는 것을 전제로 합니다.
어느 쪽을 고르든 상관없지만, 채점기는 결국 `x.in` 파일을 거둔다는 점을 기억하십시오.

채점 환경은 ARM(aarch64) 리눅스에 g++ 13 입니다. `#pragma GCC target("avx2")` 같은
x86 전용 지시자는 컴파일되지 않습니다.
